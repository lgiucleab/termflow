## Goal
A real terminal: PTYs, xterm.js with WebGL, tabs and splits, shell picker, automatic shell integration that turns each command into a **block** (command, exit code, duration, cwd, branch), block actions, command palette, themes, find, links, terminal-aware copy/paste, and launching installed agent CLIs (`claude`, `codex`, …) in their own panes.

## Design

### Data path (the part that has to be fast)
```
PTY reader thread (blocking) ──bytes──▶ TerminalSession task
   ├─▶ OscScanner (vte): OSC 133 / 6973 / 7 ─▶ BlockTracker ─▶ AppEvent::Block* ─▶ SQLite `blocks`
   ├─▶ plain-text excerpt per block (ANSI stripped, last 2 MB, capped)
   └─▶ batcher: flush every 8 ms or 64 KB ─▶ tauri::ipc::Channel (raw bytes, ArrayBuffer in JS) ─▶ xterm.write
UI keystrokes ─▶ command `terminal_write(id, bytes)`; resize ─▶ `terminal_resize(id, cols, rows)` (debounced 50 ms)
```
- Output goes over a per-pane **Tauri `Channel` sending raw bytes**, not JSON events (events would base64/JSON-encode megabytes per second). **[verify in task 1]** whether tauri-specta can type `Channel<InvokeResponseBody>`; if not, that one command is typed by hand in `bridge/` and documented.
- xterm.js also registers an OSC 133 handler so block decorations land on the exact rendered line. Rust parses the same byte stream for metadata and persistence. One stream, two consumers, no sync protocol.
- Back-pressure: if xterm falls behind (write callback pending > 1 MB), the UI tells Rust to pause reading; the PTY's own buffer then throttles the child. This is how `yes | head -n 2000000` stays responsive.

### Crates
- **`termflow-pty`**: `PtyHandle::spawn(ShellSpec, size, env, cwd)`, `write`, `resize`, `kill`, `try_wait`; dedicated reader thread → bounded channel. Shell detection: `unix.rs` (`$SHELL`, `/etc/shells`: zsh, bash, fish, nu), `windows.rs` (pwsh, powershell, cmd, Git Bash, `wsl.exe -l -q` distros). Env: `TERM=xterm-256color`, `COLORTERM=truecolor`, `TERM_PROGRAM=TermFlow`, `TERM_PROGRAM_VERSION`, `TERMFLOW_SESSION_ID`.
- **`termflow-shell-integ`**: `OscScanner` (feeds bytes, yields `Mark::{PromptStart, CommandStart, OutputStart, Finished(exit)}`, `Meta{cwd, git_branch, cmd, duration_ms, shell}`), `BlockTracker` state machine (`A→B→C→D`; out-of-order or missing marks → `Degraded`), embedded scripts in `shell-integration/` (zsh, bash, fish, pwsh) plus `inject(ShellSpec) -> (args, env, files)`:
  - zsh: `ZDOTDIR` shim that sources the user's real `.zshenv`/`.zshrc` then ours.
  - bash: `--rcfile` shim that sources `~/.bashrc` (and the login files for login shells).
  - fish: `--init-command`.
  - pwsh/powershell: `-NoExit -Command ". 'termflow.ps1'"`.
  - Opt-out: `terminal.shell_integration = false`.
  - Alternate screen (`?1049h/l`) suspends block grouping.
- **`termflow-terminal`**: `TerminalManager` (create/close sessions, owns PTY + tracker + batcher), block persistence, agent-CLI discovery on PATH (`claude`, `codex`, `gemini`, `opencode`, `copilot`, `aider`).
- **`termflow-types`**: `TerminalId`, `ShellSpec`, `Block`, `BlockStatus`, `AppEvent::{BlockStarted, BlockFinished, BlocksDegraded, TerminalExited}`.
- **`termflow-config`**: `terminal.{shell, shell_integration, font_family, font_size, ligatures, copy_on_select, warn_multiline_paste, scrollback}`, `ui.theme`.

### Degradation mode (deviation from §5.2, see below)
When marks are missing or out of order (ConPTY reordering, `ssh` into a host without integration), the pane switches blocks **off** and shows a small "blocks unavailable" indicator. The heuristic prompt detection with `alacritty_terminal` is deferred.

### UI (`apps/desktop/ui/src/features/terminal`, `palette`, `layout`)
- `TerminalView` interface wrapping xterm.js (so `ghostty-web` can replace it later): WebGL with DOM fallback, fit, search, unicode11, web-links (http/https open directly; other schemes ask first), serialize, optional ligatures.
- **Tabs and splits**: layout is a tree (`split{dir, ratio, a, b} | pane{id}`) in a Solid store; drag to resize, focus navigation, rename tab, per-tab shell profile. The layout is saved to the `settings` table and restored on restart (cwd restore is v1).
- **Blocks**: header bar per finished command (command, exit badge green/red, duration, cwd, branch) using xterm decorations at the block's prompt line. Actions: copy command, copy output, copy as markdown, **Attach to agent**, re-run, collapse/expand. Inline in the terminal, collapse/expand in place.
- **Attach to agent**: M1 adds an empty **Agent** tab type that lists attached blocks as markdown cards (no model calls until M2). This meets the acceptance item.
- **Command palette** (Cmd/Ctrl+K): actions, open tabs, recent blocks, themes, shells, "New external agent: …".
- **Keybindings**: Cmd/Ctrl+K, T, W, F, D, Shift+D, Shift+A (attach last block). macOS: only Cmd shortcuts are intercepted while a terminal is focused. Windows: Ctrl+C copies when there is a selection, otherwise sends SIGINT; Ctrl+V pastes.
- **Paste**: bracketed paste; a warning before pasting multiple lines (setting).
- **Themes**: Dark (default), Light, High Contrast, Nord, Gruvbox Dark, Catppuccin Mocha. These are UI tokens plus a 16-color terminal palette, and the open-licensed (MIT) palettes are named as plain text only. iTerm2/Windows Terminal import is v1.
- **Fonts**: bundle JetBrains Mono (OFL), plus a user-selectable font and size.
- **External agents**: "New external agent" menu lists only CLIs found on PATH. Each opens in a pane with a text badge (no vendor logos, per §9.6).

## Deviations from the brief (approved)
1. **`vte` instead of `alacritty_terminal` in M1.** We only need OSC scanning and ANSI stripping, and `vte` is the parser `alacritty_terminal` itself uses. The full grid (`alacritty_terminal`) is only needed for the heuristic fallback and v2 "full terminal use"; it comes then.
2. **Degradation = blocks off + indicator** for M1; heuristic prompt detection comes with (1).
3. **`tauri-plugin-opener`** instead of the shell plugin for opening links.
4. **No canvas renderer**: `@xterm/addon-canvas` is abandoned and incompatible with xterm 6, so WebGL falls back to DOM.

## Risks
- Windows (ConPTY, pwsh, Git Bash) can only be checked in CI and by hand: OSC reordering may push many Windows sessions into degraded mode.
- WKWebView + WebGL performance under heavy output is unproven until the spike.
- Typing a raw-bytes Channel through tauri-specta (RC) may need a hand-written bridge exception.


## As built (2026-11-22)

### Spike results
- Raw-bytes channel **works without a hand-written bridge exception**: `OpenTerminal.on_output` is a `JavaScriptChannelId` exported as `string` (`Channel.toJSON()`), resolved in Rust with `channel_on(webview)` into `Channel<InvokeResponseBody>`. JS receives `ArrayBuffer`.
- xterm 6 + WebGL render correctly in WKWebView (vim with syntax colors, full-height, alternate screen).

### Measurements (macOS arm64, **debug** build)
- `yes | head -n 2000000` (6 MB through the terminal): finished in **1.6 s**; worst frame gap **41 ms**, **0 frames > 50 ms** (dev perf monitor). Target (no freeze > 100 ms) met.
- Idle memory, one terminal tab: core process **~131 MB RSS** (debug build, unoptimized). The WebView runs in separate WebKit processes that `ps` can't attribute reliably. Proper release numbers come in M5 (`docs/PERFORMANCE.md`).

### Verified by hand on macOS
Block headers (exit badge, duration, cwd), splits (Cmd+D), the palette (Cmd+K), theme switching (Nord applied to chrome and terminals), vim at full height, git log colors.

### Deviations (beyond the approved list)
- **Windows/Linux shortcuts use Ctrl+Shift+key** (palette Ctrl+Shift+K, new tab Ctrl+Shift+T, close Ctrl+Shift+W, split right Ctrl+Shift+D, split down Ctrl+Shift+E, find Ctrl+Shift+F, attach Ctrl+Shift+A). Plain Ctrl+K/T/W/D/F all mean something inside shells (kill line, transpose, delete word, EOF, forward char). macOS uses Cmd as specified.
- **Collapsing a block covers its output in place** instead of removing the lines: xterm.js can't drop lines from its buffer. The space stays; the content is hidden behind a "N lines collapsed" bar.
- The header overlays the prompt's first line. With multi-line prompts or a long wrapped command, the remaining prompt lines stay visible under it.
- Restored layouts reopen agent panes as plain shells, so an agent CLI never relaunches by surprise.
- Block headers appear when a command **finishes**. There's no "running" header yet; the status bar shows cwd.
- `TERMFLOW_DEV_AUTORUN` (debug builds only) types a command into every new terminal. It's the harness for the perf and rendering checks.
- No cargo-fuzz target. The scanner has proptest coverage instead (random chunking gives identical events; random bytes never panic).

### Tests
- Rust: scanner (incl. proptest), tracker (lost `D`, double `C` → degraded, repeated marks, alt-screen exclusion, excerpt cap), injection, PTY spawn/IO/resize/exit code, **real zsh and bash sessions** producing blocks with the right command, exit code, seq and cwd, block + settings persistence. Windows `pwsh` real-session test runs in CI only.
- UI (vitest): layout model, fuzzy ranking, keybinding routing, block markdown, palette interaction.

### Known issues / not verified
- Windows `ConPTY` (via portable-pty's `INHERIT_CURSOR` flag) sends nothing until the terminal answers its first cursor query (`ESC[6n`). xterm.js answers it in the app. **Any headless consumer (the v1 daemon/CLI) must answer it too.** The Windows test does.
- fish isn't installed here: its test is skipped locally and on CI runners that lack it. The script is untested.
- Windows (ConPTY, pwsh, Git Bash) is untested by hand. CI runs the pwsh session test, and the manual checklist has the rest.
- `htop`/`btop` aren't installed here, and claude/codex TUIs weren't launched in this pass. Both are on the manual checklist.
- Ligatures depend on local-font access in the WebView. They're off by default and silently unavailable if the API is missing.
