# M3 — Router with fallback (approved)

Branch: `m3-router` (from `m2c-unified`). Status: **M3a built** (router core); M3b (switch UX) next. Source: `BUILD_PROMPT.md` §7 and §12 (M3).

## Goal
A chat keeps working when its model hits a limit, an outage or a context ceiling. The router moves the request to the next model in the user's **profile** (different providers, plans or the user's own distinct keys; never a multi-account rotator, see CLAUDE.md legal rule 4). It does this without losing the turn, re-running a tool or silently spending on a paid model past the budget. The user always sees why it switched.

## What exists (M2)
- Typed `ErrorClass` from all four adapters (HTTP, body codes, mid-stream SSE errors), with fixture tests.
- `Router::stream` is a pass-through to one `(credential, model)` that writes an `attempts` row (tokens, TTFT, served model, class).
- The canonical transcript keeps native reasoning with `family`/`credential_scope`. `may_resend` drops it for other vendors. `id_map` holds native call ids, and `exec_count` stops a tool from running twice.
- The agent marks a failed partial turn `Discarded` and stops with an `AgentError`.
- The mock provider has scripted statuses, headers, SSE chunks, delays, stalls and request recording.

## Design

### Split into two PRs
- **M3a — router core (backend, fully tested).** Everything in acceptance (a)–(l) plus the property tests. The UI gets only what it needs to stay correct: the model picker can choose a profile, and the "All models unavailable" and budget-stop states show as a plain banner.
- **M3b — switch UX.** The switch banner, the per-turn "Why did it switch?" attempt timeline, health dots for each chain member, pin/Auto, the live cost meter, and a profile editor. Mono styling throughout.

### Profiles (`termflow-config`, `[profiles.*]` + `[routes]`, as in §7.6)
- A chain entry is `provider/model@credential-label` (Ollama needs no `@`). Model ids come from the provider's model list or the catalog; we never invent ids.
- Options: `on_context_overflow`, `on_content_policy`, `retry { transient_max_wait_s = 10, overloaded_retries = 2 }`, `hysteresis_turns = 3`, `switch_back = when_healthy|never|ask`, `budget { session_usd, day_usd, month_usd, hard_stop }`, `require { tools, vision, reasoning }`, `handoff_note = true`.
- A session has either a **profile** or a **pinned model**. A pinned model is the M2 behaviour, a chain of one. Existing sessions keep working unchanged.
- Profiles can also be created and edited from the UI (stored in the global config file). The M3a UI only selects them; the M3b editor writes them.
- `[routes]`: `background` (chat titles) and `compaction` are wired up. `long_context`/`vision` are honoured by the capability filter.

### Router pipeline (new modules in `termflow-router`)
| Module | Job |
|---|---|
| `clock.rs` | `Clock` trait (real + fake) for every wait, cooldown and reset. Tests never sleep for real. |
| `health.rs` | `HealthRegistry` keyed by `(provider, model, credential)`. Closed → Open (N failures in a window, or immediately on quota/auth) → HalfOpen after cooldown (≥30 s; for quota, until `reset_at`) → Closed on success. Persisted in SQLite, so a restart remembers quota resets. |
| `ratelimit.rs` | Parse `anthropic-ratelimit-*` and OpenAI `x-ratelimit-*` headers from every response. Adapters expose the headers; the router decides. |
| `select.rs` | Chain → capability filter (tools/vision/reasoning/context ≥ estimate/max price) → health/budget filter → context fit → ordered candidates. Applies hysteresis. |
| `policy.rs` | The §7.6 action table as a pure function: `(ErrorClass, attempt state, profile) → Retry{after} / Next / Overflow / ContentPolicy / StripNativeRetry / Surface`. Most of the tests live here. |
| `ledger.rs` | `BudgetLedger`: cost per attempt from catalog prices of the **served** model (input, output, cache write/read, reasoning). Session/day/month totals, soft warning at 80 %, hard stop. |
| `patterns.rs` | Classifier patterns in code, plus an optional user `error_patterns.toml` in the config dir that adds to or overrides them. |
| `estimate.rs` | Token estimate (chars/≈3.5 heuristic plus a safety margin; shortcut documented). |

- `Router::stream` keeps its signature but takes a `RouteTarget = Profile(id) | Pinned{cred, model}`. Retries and switches happen **before the first byte reaches the agent**: the router buffers until the first content event.
- After content has started, a failure ends the stream with a typed `Handoff` error. The agent then discards the partial turn (as today) and calls the router again from the last committed turn, with the failed target excluded. The user types nothing (acceptance c).
- **Hand-off (§7.7):** native parts are re-sent only to the same family and credential scope, and other vendors get plain text plus tool calls and results. A one-line `HandoffNote` is added on cross-vendor switches. Tools already run keep their `ToolResult` and are never run again: the existing `exec_count` guard, asserted in a test (f).
- **All candidates down:** the session is paused with each candidate's state and reset time. It resumes by itself at the earliest reset (fake-clock test k), or the user picks a model.
- **Budget hard stop:** the agent pauses with a dialog. The router never falls through to another paid model when the budget is the reason (l).

### Context overflow (acceptance d)
M3 uses `on_context_overflow` and the `long_context` route. If neither fits, M3 drops the oldest **tool-result bodies** (never the system prompt, the last N turns or any unresolved call/result pair) and re-checks. Full structured compaction with checkpoints stays in M4 (§6.8), as the milestone plan says.

### Model catalog (`termflow-catalog`)
- Fetch the models.dev `api.json` for context window, max output, capabilities and prices. OpenRouter models come from its own models endpoint, which we already call for its models list. The data is cached in SQLite and refreshed daily; offline, the cache is used.
- **Fetched only when at least one provider is configured** (zero outbound requests otherwise, §10/M5). The first fetch is disclosed in the providers dialog.
- Users can override any field (`[catalog.overrides."provider/model"]`). Ollama models get capabilities from `/api/show`, and small local models are flagged "tool use may be unreliable".
- An unknown model has unknown capabilities and price. It is still usable, but the budget cannot be enforced for it, and that is shown.

### Events (new `AppEvent` variants)
`RouteSwitched { from, to, reason, until }`, `RouteWaiting { target, seconds }`, `RoutePaused { candidates[] }`, `BudgetWarning`, `BudgetStopped`, `CredentialAuthFailed`. M3a only renders them as a plain banner; M3b builds the full UX.

### Mock provider additions
Scripts for the Anthropic and OpenAI rate-limit headers. A second mock instance gives a "different vendor" in tests. Fixtures (all written from public docs): 529 `overloaded_error`, 503, 413, 401, invalid-signature 400, stall, and an SSE error after N tokens, each in Anthropic, OpenAI Responses and OpenAI Chat formats.

## Acceptance
Every §12 M3 item (a)–(l) is an automated test against the mock provider with a fake clock, plus the property tests. Manual: with a real Anthropic key at its spend limit and a working OpenAI key, a chat switches mid-task and finishes. This goes in `MANUAL_TEST_CHECKLIST.md`.

## Risks / limits
- **Gemini is not supported yet.** No Google adapter exists, so §7.6 examples that use `google/…` need a custom OpenAI-compatible endpoint, or wait for a Gemini adapter (v1).
- **Token estimates are approximate.** The margin protects against overflow, and a real overflow is still caught by the 413/400 path.
- **The catalog is a third-party data source.** Prices can be stale or missing; overrides fix that, and the ledger shows "unknown price" instead of guessing.
- **Mid-stream switching discards streamed text** (the spec allows keeping it optionally). M3 drops it for simplicity, and the new model answers in full.

## As built (M3a)
- **Router** (`crates/termflow-router`):
  - `clock` (`Clock`, `SystemClock`, `FakeClock`).
  - `policy` (the §7.6 table as a pure `decide()`).
  - `health` (breaker: 3 failures in 60 s, at least 30 s cooldown, half-open probe; plus credential-wide quota/auth blocks persisted in `route_blocks`).
  - `select` (`provider/model@label` resolution and capability/fit checks).
  - `estimate` (JSON length / 4; trims old tool output when nothing fits).
- **The `Router::stream` loop:**
  - It takes `RouteTarget::Pinned | Profile` and holds the stream back until the first content event, so failures before that are retried or switched inside the router.
  - Rate-limit headers from every response move a target to the back when the next request won't fit.
  - Hysteresis is counted per successful request.
  - When every candidate is down, the chat pauses and sleeps on the router's clock until the earliest reset, up to 3 times (Esc cancels).
  - A hand-off note is added to the system prompt on cross-vendor requests (not stored in the transcript).
- **Agent:**
  - A profile chat hands a mid-stream failure to the next candidate, up to 2 times per step. The partial turn is kept as `Discarded`, and tools run only after commit, so nothing re-runs.
  - A pinned chat keeps the M2 behaviour (the error is shown) but gains the retry table before the first byte.
  - Picking a model pins it and clears the profile.
- **Budget:**
  - Session/day/month limits, in UTC, over all attempts.
  - The cost of each attempt comes from catalog prices of the **served** model. Failed attempts cost 0, and an unknown price stays `NULL`.
- **Catalog:**
  - The models.dev `api.json` is cached in `catalog_cache`.
  - It is fetched at startup and after adding a provider, at most daily, only when a provider exists and `catalog.fetch` is not `false`.
  - Users can add `[catalog.overrides."provider/model"]` entries.
- **Config:** `[profiles.<name>]`, `[routes]` and `[catalog]` (schema regenerated). `switch_back` is `when_healthy | never`; `ask` was dropped until M3b has the UI for it.
- **UI (minimal):** a profile picker in the chat header (shown when profiles exist) and plain notes/banners for `route_switched`, `route_waiting`, `route_paused`, `budget_warning` and `budget_stopped`.
- **Tests:**
  - (a), (b), (d), (e), (g)–(l) are router tests against two mock providers and a fake clock.
  - (c) + (f) are an agent test.
  - The property test renders 200 random histories × 4 wire formats and checks balanced, ordered, unique call/result pairs, with no foreign thinking blocks.
- **Not in M3a (moved):**
  - `[routes]` are parsed but not used yet (titles still come from the first line; there is no compaction yet).
  - There is no vision filter (no image parts exist yet).
  - Ollama `/api/show` capabilities and the small-model warning are deferred to M3b.
  - Per-credential budgets are not built.
  - Budgets apply to profiles only, not pinned models.

### Example
```toml
[profiles.main]
chain = ["anthropic/<model-id>@personal", "openai/<model-id>@work", "ollama/<local-model>"]
on_context_overflow = ["openrouter/<long-context-model>@openrouter"]
budget = { day_usd = 10.0 }
```
