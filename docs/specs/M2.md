## Goal
TermFlow's own coding agent, end to end, on **one model at a time**. You add API keys (stored in the OS keychain), pick a model, chat in an Agent tab, and the agent reads code, proposes changes, runs commands after you approve them, and reports back. It works against Anthropic, OpenAI, any OpenAI-compatible endpoint, and Ollama. Every model call already goes through `termflow-router` (a pass-through in M2) and the canonical transcript, so M3's fallback slots in without changing the data model.

**Anthropic Messages API (current, verified):**
- Header `anthropic-version: 2026-10-21`. On this version `temperature`/`top_p`/`top_k` are rejected, so the adapter never sends them.
- Thinking: `thinking: {type: "adaptive"}`, depth via `output_config.effort`. `budget_tokens` is rejected on current models. `display` defaults to `"omitted"`, so we send `"summarized"` to show readable reasoning.
- Thinking blocks (with signatures) must be passed back **unchanged**. The API silently drops, unbilled, any block the current model can't read. Our append-only transcript already satisfies the "no history editing" check.
- Forced `tool_choice` (`any`/`tool`) is a 400 on current models, so we always use `auto`. Assistant prefill is a 400, so we never end a request on an assistant turn.
- Streaming event types: `message_start`, `content_block_start/delta/stop` (`text_delta`, `thinking_delta`, `signature_delta`, `input_json_delta`), `message_delta` (stop reason + usage), `message_stop`, `error`.
- Spend-cap 429: `error.details.error_code = "enforced_spend_limit_reached"`, with no `retry-after`. 529 is `overloaded_error`.
- `GET /v1/models` lists models with `max_input_tokens`, `max_tokens`, `capabilities`.

**OpenAI Responses / Chat Completions, Ollama:** wire details (Responses streaming event names, `reasoning.encrypted_content` with `store: false`, Ollama's `/api/chat` vs its `/v1` endpoint) get **[verified against current docs in task 1]** and pinned as recorded fixtures before the adapters are written.

**Model IDs:** none are hard-coded. The model picker lists what each provider's models endpoint returns (`/v1/models`, Ollama `/api/tags`). Real IDs appear only in test fixtures.

## Design

### Data flow
```
Agent tab ──send──▶ termflow-agent (loop) ──RenderRequest──▶ termflow-router ──▶ ProviderAdapter.stream()
   ▲                    │  tool calls                                  (M2: single target, pass-through)
   │                    ▼
   │              termflow-perms ──ask──▶ UI approval card ──▶ decision
   │                    ▼
   │              termflow-tools (read, write, edit, apply_patch, bash, grep, glob, ls, todo, attach_block, webfetch)
   │                    ▼
   └── AppEvent::Agent* ◀── transcript events, committed to SQLite before publishing
```

### Crates
- **`termflow-types`**: `Turn`, `Part`, `Role`, `TurnStatus`, `ServedBy`, `ToolResultContent`, `StreamEvent`, `Usage`, `StopReason`, `ProviderId`, `ModelRef`, `AgentMode`. `Part::Reasoning` stores the provider-native block verbatim. Agent events: `AgentTurnStarted/Delta/Committed`, `ToolCallRequested/ApprovalNeeded/Finished`, `AgentStatus`.
- **`termflow-secrets`**: keychain wrapper (`set`, `get`, `delete` under service `com.flowlabs.termflow`) and `secret://<id>` resolution. Every resolved value is registered with the redactor.
- **`termflow-providers`**: the `ProviderAdapter` trait from BUILD_PROMPT §7.2 (`render`, `stream`, `classify`, `parse_rate_limit_headers`, `list_models`). Adapters: `anthropic`, `openai_responses`, `openai_compatible` (Chat Completions; OpenRouter, Groq, DeepSeek, LM Studio, vLLM, custom), `ollama`. `classify` already maps errors to `ErrorClass` (fixtures for each signal). M3 adds the router's actions on top.
- **`termflow-router`**: M2 = pass-through. Resolve profile → single target → credential → adapter. Every attempt is written to the `attempts` table (status, `ErrorClass`, tokens, TTFT, latency). Errors are surfaced, never retried, because retry/fallback is M3.
- **`termflow-tools`**: tool trait (name, JSON schema, `is_mutating`, default permission, LLM-facing description, timeout). Full result stored in the DB; truncated for the model with an explicit note (§6.2).
  - `bash` runs in its own non-interactive process (not the visible terminal) with a timeout (120 s default, 10 min max), head+tail output cap and exit code. `background: true` with `bash_output`/`bash_kill` arrives in v1.
  - `apply_patch`: format per the owner's answer below; the parser gets proptest coverage.
- **`termflow-perms`**: ordered rules, last match wins, `deny` beats everything. The default rule set is from §6.4. Plan mode denies mutating tools **in this layer**, not just in the prompt. Approval broker: Allow once / Allow for session / Deny / Deny with feedback. "Always allow" (writes config) and presets come in M4.
- **`termflow-context`**: discover `AGENTS.md`, `CLAUDE.md`, `.termflow/rules/*.md` from cwd up to the git root, plus global `~/.config/termflow/AGENTS.md`. Ignore rules come from `.gitignore`/`.ignore`/`.termflowignore`. Secrets files (`.env*`, `*.pem`, `id_*`) are never read automatically. Handles `@file` and `@block` expansion.
- **`termflow-agent`**: the loop (§6.1). Read-only tools run concurrently; mutating tools run one at a time, in order. Step limit 50. Esc cancels the stream and any running tool, keeps partial text as text, and records the cancellation.
  - Modes: `build` and `plan`.
  - System prompt = versioned `prompts/system/base.md` + mode addendum + environment + project context + tool descriptions.
  - Slash commands: `/plan`, `/build`, `/model`, `/clear`, `/attach`, `/init`, `/help`, `/cost` (this session's tokens; $ needs M3's price catalog). `/profile`, `/compact`, `/undo`, `/redo` print "arrives in M3/M4".
- **`termflow-store`**: migration `0003`: `parts` JSON for the new `Part`s, `tool_calls`, `id_map` (tables already exist), `credentials(id, provider, label, base_url, secret_ref, created_at)`. On startup, any `Partial` turn becomes `Discarded`, which restores the session to its last committed turn.

### UI
- **Settings → Providers**: add/remove credentials (API key goes straight to the keychain, never shown again), base URL for custom/OpenAI-compatible endpoints, "Test connection" (lists models, shows ✓ or the classified error). Local: detect Ollama on `localhost:11434`.
- **Agent tab** (replaces the M1 placeholder):
  - Virtualised message list.
  - Streaming Markdown with highlighted code blocks (copy / insert into terminal).
  - Collapsible tool cards (name, args summary, status, duration, result preview).
  - Inline approval cards showing the exact command or diff.
  - Reasoning collapsed; "served by <model>" badge on each answer.
- **Chat input**: multi-line, Enter sends / Shift+Enter newline, Esc stops, `/` and `@` autocomplete, Plan/Build toggle (Shift+Tab), model picker, shows which context files are loaded.
- Attached blocks from M1 become `@block` context on the next message.

## M2a as built (2026-11-22)

### What exists
- **Transcript** (`termflow-types::transcript`): `Turn`, `Part` (text, tool call/result, provider-native reasoning), `StreamEvent`, `Usage`. Persisted append-only (`termflow-store::agent`). A streamed turn is `partial` until it commits atomically, and startup marks any leftover `partial` turn `discarded`, so it's never resent.
- **Secrets** (`termflow-secrets`): `KeychainStore` (keyring 4, v1 API) and `MemoryStore` for tests, behind `Secrets`, which registers every value with the redactor. A test asserts that no file under the data dir contains the key.
- **Providers** (`termflow-providers`):
  - `anthropic`, `openai_responses`, `openai_chat` (incl. OpenRouter `reasoning_details` passthrough), and `ollama`
  - each with render, SSE/NDJSON streaming, error classification, and `list_models`
  - a stall detector (120 s) and cancellation
  - native reasoning is re-sent only to the same family and credential (insta snapshots prove it)
- **Router** (`termflow-router`): a pass-through to the session's one target. Writes an `attempts` row per request (status, error class, TTFT, tokens, served model), including failures. Never retries; that's M3.
- **Chat** (`termflow-agent`):
  - streams a reply, commits it, publishes `AgentTurnStarted/Delta/Committed/Error`
  - **mid-stream errors discard the partial turn**
  - **Esc keeps partial text** (marked `[cancelled]`) and drops half-finished reasoning and tool calls
  - session titles come from the first message
- **Mock provider** (`tests/mock-provider`):
  - scriptable axum server: queue, pacing, stall, recorded requests
  - also a dev binary: `cargo run -p mock-provider -- tests/fixtures/http/ollama/text_tool.ndjson`
- **UI**:
  - Providers dialog (presets + custom endpoint; the key field is cleared after saving; Test lists models)
  - Agent tab: per-session model picker with a reasoning toggle, streaming Markdown (marked + DOMPurify), collapsed reasoning, "served by" badge, error banner with the classified reason, Stop/Esc
  - M1-attached blocks are sent as context with the next message
  - The agent pane remembers its session across restarts.

### Deviations
- `StreamEvent::ReasoningDone { native, summary_text }` delivers the *complete* native block from the adapter, instead of fragments assembled by the caller. `ServedModel` was added for gateways.
- Error patterns are in code. The overridable `error_patterns.toml` arrives with M3's router logic.
- Rendering uses our `CallId` as the tool-call id for every provider. Mapping back to native ids (`id_map`) comes in M2b, when tools actually run.
- OpenAI Responses: we replay the assistant *text*, not the full native message item, so `phase` isn't preserved yet. Reasoning items are replayed verbatim.
- Output cap is 16 000 tokens per request. Per-model limits come from the M3 catalog.
- Reasoning is a per-session toggle, because some models reject reasoning parameters (e.g. non-reasoning OpenAI models, Ollama models without `think`).
- `dangerously_cast_bigints_to_number` is enabled on the bindings, since `serde_json::Value` contains 64-bit numbers. IPC is JSON-parsed in JS, so they are JS numbers anyway.
